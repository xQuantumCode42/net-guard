# NetGuard 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement the approved native desktop network protection design as version 1.0.0, preserving honest platform capabilities and verification gates.

**Architecture:** Rust workspace with policy/storage core, native platform adapters, an independent privileged agent and a Tauri desktop application. Local OS-restricted IPC separates the unprivileged UI from enforcement. UI reports effective enforcement separately from observed connections and simulated rule evaluations.

**Tech Stack:** Rust 1.90, SQLite, serde, Windows WFP, Linux nftables, macOS Network Extension, Tauri 2, React/TypeScript/Vite.

**Spec:** ../specs/2026-11-21-netguard-design.md

## Global Constraints

- Version is 1.0.0 in every package; no automatic version increment. Only the user authorizes future version changes.
- Support targets: Windows, latest stable macOS, Ubuntu and Arch Linux; untested targets must remain explicitly unverified.
- No vendor names or vendor dependencies in product documentation.
- No TLS interception, no invented domain/process identities, no simulated enforcement reported as actual protection.
- Installation/enabling privileged protection is an explicit user action; builds and tests do not disable other security software or change production routing/DNS.
- Existing project directory has no Git repository; work in the dedicated netguard directory, initialize an implementation branch locally, no remote publication.

## Review Focus

- An expired allow rule must not keep allowing in the native backend: core expiry tests and agent refresh.
- Invalid imports must not erase the last valid policy: SQLite transaction tests.
- Unknown hostname must not match a domain allow: policy tests and unsupported native rule reporting.
- Agent failure must not leave UI reporting active protection: IPC error integration test and UI disconnected state.
- Native filter compilation must preserve ordered rules and avoid shell injection: backend compiler tests with scoped permits and malicious input.
